# Milestone report template

Every milestone report in `reports/milestones/` uses these 15 fields, in this
order. A field that cannot be completed reads
**PENDING --- <who/what it awaits>** and names the exact evidence expected.
No field is deleted, and none is answered with "n/a" where evidence is simply
missing.

---

## 1. Milestone ID and title

## 2. Date and author

## 3. Objective
What this milestone was supposed to achieve, in the blueprint's terms.

## 4. Scope boundaries
What was explicitly *not* done, and which milestone owns it instead.

## 5. Inputs
Data, documents, decisions, and prior commits this work depended on, with hashes
or SHAs where they exist.

## 6. Method
What was actually done, in enough detail to repeat it.

## 7. Outputs and deliverables
Every file produced, by repo-relative path.

## 8. Evidence
Command output, hashes, counts. Raw, not paraphrased.

## 9. Verification and checks
Which checks were run, and their results: tests, scans, smoke tests.

## 10. Run records
Repo-relative paths of the run records backing the evidence above.

## 11. Decisions made or invoked
Decision-log IDs, with status.

## 12. Deviations from the work package
Anything done differently from the issued package, and why.

## 13. Open questions and blockers
What is unresolved, who owns it, and what it blocks.

## 14. Gate criteria assessment
Each gate criterion from `docs/PROJECT_PLAN.md`, verbatim, with MET / NOT MET /
PENDING and the evidence for that judgement.

## 15. Next actions
Concrete next steps with owners.
