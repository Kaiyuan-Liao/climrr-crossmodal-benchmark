## Q0 — Is there any other authoritative material about this file?

**Affects potentially all 275 columns**, by way of Q1–Q18 rather than directly.

Every question below is asked because the tracked 19-page dictionary does not
answer it. A second source document could answer many of them at once, and
GUIDANCE has already named that class of evidence as sufficient to promote a
mapping: alongside explicit confirmation from the mentor or the ClimRR authors,
it accepts "an authoritative export/source-generation specification" and
"another authoritative ClimRR artifact explicitly mapping full CSV names to
dictionary sections" (`M1_WP1_GUIDANCE_REVIEW.md` §1). So this question is worth
asking before the rest: an answer in conversation settles one question, a
specification settles a family of them.

**Question, for the mentor / ClimRR authors.** Is there any other authoritative
material about this file that we should have?

1. **A newer or more complete data dictionary** than the 19-page PDF tracked at
   `data/metadata/ClimRR_Metadata_and_Data_Dictionary.pdf`. Ours is dated
   September 14, 2023 (line 38), says its field names were last updated
   8/25/2023 (line 81), and describes itself as covering the **alpha release**
   of the ClimRR portal. It also has no field table for the FWI classes (Q8) or
   the `precipdaily_*` family (Q7), and the defects in Q2–Q4 may already be
   fixed in a later revision.
2. **A document, script, or ArcGIS project describing how `FullData.csv` was
   assembled** from the ClimRR layers and the Census and socioeconomic sources.
   Per D-008 the join happened before the file reached this project, so this is
   the only thing that could answer Q1, Q10, Q11 and Q12 by evidence rather than
   by recollection. An ArcGIS model, a toolbox, a Python or R script, or even
   the field-mapping table from the join would each do.
3. **A ClimRR web page or release note naming the data version and export
   date** — Q18. The portal's own documentation may date the release this export
   came from even if the file itself does not.

**If any such artifact arrives, it is handled like the data dictionary was, and
for the same reason (D-002, D-005).** Before a single sentence of it is cited:
the file is placed under `data/metadata/`, its SHA-256 and byte size are
recorded in `data/manifest.json`, and — if it is a PDF — its text is extracted
by a pinned extractor into a tracked, never-hand-edited file so that every
citation carries a line number traceable to those bytes. An artifact that is
quoted before it is pinned is an artifact whose provenance cannot be
reconstructed later, and this project has already decided not to do that. A
script or a project file that cannot be text-extracted is still pinned by hash
and cited by path and line.

Receiving such an artifact does **not** by itself change any column status. It
becomes a resolution record in `../data/metadata/resolutions.yaml` with
`source: authoritative_artifact` and a `source_detail` naming the document and
its hash, and the record must still name the columns or the stems it settles.

## Q1 — Is `FullData.csv` the eleven dictionary layers joined side by side?

**Affects 101 columns: indices 5–105.** This is the single question that most
reduces the inventory — 75 of those columns are `partially_resolved` purely
because of it, and the remaining 26 are the defects and spellings in Q2–Q6.

The dictionary describes **eleven separate gridded layers**, each with its own
field table, and inside a table it names fields by suffix only — `HIST`,
`RCP45_MIDC`, `MID85_45` — with the variable carried by the section title above
(for example "Temperature Maximum - Annual", line 513). The CSV instead carries
`tempmaxann_rcp45_midc`: a stem, then that same suffix.

The dictionary never states that a CSV stem denotes a section, so the
correspondence is an inference about how the export was produced.

**Partly answered (D-008, stated by Kaiyuan, not independently verified).** The
file was shared by his mentor from ALCF through Box, downloaded as a single file,
and **no operation of any kind was applied to it afterwards**. So whatever
produced this layout happened before the file reached this project. That removes
one possibility --- that the stems were added during handling here --- and makes
this a question for the mentor and the ClimRR authors rather than one recoverable
from Kaiyuan's steps. It does not answer the question itself, and **no column's
status changed on the strength of it**: the statement names no dictionary section
for any stem.

## Defects in the dictionary itself

These are not gaps; they are places where the source document contradicts
itself or is blank. They cannot be resolved by reading it more carefully.

### Q2 — Six fields under "Precipitation None" have no description at all

**Affects indices 16–21** (`noprecip_mid45_hist`, `noprecip_end45_hist`,
`noprecip_mid85_hist`, `noprecip_end85_hist`, `noprecip_mid85_45`,
`noprecip_end85_45`).

The table at line 601 describes `hist` through `rcp85_endc` as "Consecutive Days
with No Precipitation – Annual Ensemble Mean – …" and then lists six more field
names — **lines 608, 609, 610, 611, 612, 613** — with the description column
empty.

**Question.** What do these six fields hold? By analogy with the other tables
they would be changes and differences between periods, but the document does not
say so. What is the unit — days?

### Q3 — `MID85_45` and `END85_45` appear twice under "Temperature Maximum - Annual", the second pair describing *Minimum* temperature

**Affects indices 53–54 and 84–85.**

Under the section title "Temperature Maximum - Annual" (line 513):

- line 527 `MID85_45` — "Max Daily Temperature (°F) – Difference in Annual Average – Mid-Century RCP4.5 and Mid-Century RCP8.5"
- line 528 `END85_45` — "Max Daily Temperature (°F) – Difference …"
- line 529 `MID85_45` — "**Min** Daily Temperature (°F) – Difference …"
- line 530 `END85_45` — "**Min** Daily Temperature (°F) – Difference …"

The "Temperature Minimum – Annual" table (line 450) contains **no** `mid85_45`
or `end85_45` rows, so the two Min rows appear to have been typed into the wrong
table.

**Question.** Do CSV indices 84–85 (`tempminann_mid85_45`,
`tempminann_end85_45`) correspond to lines 529–530, and indices 53–54
(`tempmaxann_mid85_45`, `tempmaxann_end85_45`) to lines 527–528?

### Q4 — The seasonal-minimum winter rows all read "Annual Average – Historical" regardless of scenario

**Affects indices 87–90** (`tempmin_seas_rcp85_midc_winter`,
`tempmin_seas_rcp85_endc_winter`, `tempmin_seas_mid85_hist_winter`,
`tempmin_seas_end85_hist_winter`).

In "Temperature Minimum – Seasonal" (line 467), lines 475–482 give
`rcp45_midc_winter`, `rcp45_endc_winter`, `rcp85_midc_winter`,
`rcp85_endc_winter`, `mid45_hist_winter`, `mid85_hist_winter` and
`end85_hist_winter` all the *same* description — "Winter - Min Daily Temperature
(°F) – Annual Average – Historical" — while the corresponding spring, summer and
autumn rows correctly name each scenario and horizon. Line 480 breaks the
pattern differently, giving `end45_hist_winter` an End-Century RCP4.5 change
description.

**Question.** Should the winter rows read like their spring/summer/autumn
counterparts (Mid-Century RCP8.5, End-Century RCP8.5, and the two changes
against Historical)? Until this is answered the scenario of these four CSV
columns is not established by the dictionary.

## Families with no dictionary entry at all

### Q7 — What are the 56 `precipdaily_*` columns?

**Affects indices 119–174 — the largest undocumented family in the table.**

No field table in the dictionary lists any `precipdaily` field, and no narrative
section describes one. The names decompose into a season (`winter`, `spring`,
`summer`, `autumn`), a statistic (`mean`, `max`) and a period or transform:
`hist`, `mid85`, `end85`, `D…`, `P…`.

**Questions.**
1. What variable do these hold, and in what unit? Every non-empty value is
   decimal, none is empty, and the observed range for index 119 is
   `0.009570430000000` … `0.863123000000000`.
2. Do `D` and `P` mean difference and percent change, as the Fire Weather Index
   table uses them at lines 650–653? Against which baseline?
3. `mean`/`max` is truncated to `mea` in the summer and autumn columns
   (for example index 148 `precipdaily_mid85mea_summer` versus index 120
   `precipdaily_mid85mean_winter`). Same quantity, truncated name?
4. There are no RCP4.5 members in this family. Is it RCP8.5 only?

### Q8 — What do the 30 FWI-class columns hold, and what do `_95` and `_NC` mean?

**Affects indices 205–234** (`FWI_Bins_*`, `FWIBins_*`). No field table lists
them. The only related passage is the narrative "Calculating FWI Classes"
(line 357) with its class table at line 376.

Computed facts that make the question precise:

- The `_NC` columns hold **text**, 6 or 7 distinct values, maximum length 12.
  For index 206 the values by frequency are `High` (15,879), `Medium` (15,835),
  `Low` (15,222), `Very High` (9,529) — which are the class names the narrative
  defines at lines 377–383 (Low, Medium, High, Very High, Extreme, Very
  Extreme).
- The `_95` columns hold decimals; index 205 ranges
  `0.051895890000000` … `74.270507660000007`.

**Questions.**
1. Do the `_NC` columns carry the six FWI classes from line 376, and do the
   `_95` columns carry the 95th-percentile FWI values those classes are cut
   from?
2. What does `NC` abbreviate?
3. `FWI_Bins_*` (205–210) uses an underscore and covers Hist/MidC/EndC annually,
   while `FWIBins_*` (211–234) drops it and adds a season. Are they the same
   quantity at two aggregations?

### Q9 — What are the seven socioeconomic columns, and is index 117 usable at all?

**Affects indices 112–118.** No dictionary entry; the names are truncated at 30
characters (`Percentage_of_the_population_65`,
`Pop_below_U_S__Census_poverty_l`, `The_net_migration__internationa`).

**Questions.**

2. **Index 117 `Aggregate_Resilience_Indicator_` is the constant `-9` on all
   62,834 rows.** Is `-9` a no-data code? If so the column carries no

3. What distinguishes index 116 `Aggregate_Resilience_Indicator` (12,838
   distinct values, range `0.00117` … `99.9941`) from index 117?
4. Indices 112, 113, 115, 116 and 118 are empty on exactly 241 rows, while 114
   is empty on none. What are those 241 rows?

**Questions, for the mentor / ClimRR authors.**

The `_1` and `_12` suffixes are the spelling a join produces when a column name
collides. Per D-008 that join was not performed here --- the file arrived in this
shape --- so the question is for the mentor, not a matter of reconstructing local

Computed facts:

**Questions.**
1. Are `Crossmodel`, `Crossmodel_1` and `Crossmodel_12` the same identifier

2. Which single column is the authoritative grid-cell key for joining?

### Q17 — Does any flagged value mean "missing"?

The profile flags 24 columns whose numeric extreme repeats on at least 0.5% of
rows; the list is in `DATA_NOTES.md` §1. **The flag is frequency only and asserts
nothing.** Two cases need an answer before any downstream use:

1. Index 117 holds `-9` on every row (see Q9.2).
2. `0.000000000000000` is frequent in several columns — 54,443 rows of index 243
   `heatindex_HIS_Day125`, 2,889 of index 115. For a count of days above 125 °F a
   zero is plainly a real count; for a percentage column it may not be.

**Question.** For each flagged column, is the flagged value a real measurement,
or a fill code? A per-column answer is needed; a general rule is not enough.
